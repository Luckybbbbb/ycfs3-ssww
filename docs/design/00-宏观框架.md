# 00 - 游戏宏观框架

> 版本 v0.2（草案，数值未冻结）。上游索引见 [README.md](README.md)。
> v0.2 变更：核心循环拆「主角链/消除触发链」双链路；养成体系改货币+材料+抽卡；消除规则升级连通块判定；交互升级果冻拖拽与消除演出。

## 1. 一句话定位

竖屏放置+三消双区联动单机页游：玩家只操作下半 65% 的 8×8 五行三消棋盘，消除产物自动转化为上半 35% 战斗区里主角的技能释放（主角装配技能按 CD 自动释放 + 消除触发同属性随机技能），主角全自动战斗，击杀产出货币/材料用于局外养成（升级、抽卡），按关卡推进难度。

## 2. 技术路线决策记录

| 项 | 决策 | 依据 |
|---|---|---|
| 引擎 | 纯 HTML5 Canvas 2D（D1） | 参考项目 godot-extraction-shooters 已验证该路线可承载同量级玩法；本项目无 Godot 特有需求 |
| 资源 | 直接复用 godot-roguelike 的 `assets/sprites/` 序列帧 PNG（单帧文件，非图集） | `drawImage` 逐帧绘制即可，零转换成本（24MB，目录清单见 04 文档第 6 节） |
| 模块化 | ES modules + 本地静态服务 | 原型期现代浏览器全支持；`file://` 协议下 ES modules 受 CORS 限制，须本地静态服务 |
| 后端 | 预留接口（D2） | `api.js` 统一封装 fetch，本地实现回落 localStorage，接口签名与未来 REST 一致 |

**明确不做**：Godot 工程、图集打包、WebGL、存档加密、服务端（原型期）。

### 3.1 战斗区表现：远中近景视差（v0.1 增补）

放置战斗镜头固定，动态感全部来自场景层自身的运动。战斗区 448px 内分三层视差 + 动效：

| 层 | 视差系数 | 内容 | 动态效果 |
|---|---|---|---|
| 远景 | 0.15 | 天空渐变（晨→昏随波次推移）、远山/树林剪影 ×2、太阳/月亮 | 云朵 2~3 朵横移循环（60~90s/圈）；Boss 波天色压暗 tint |
| 中景 | 0.45 | 树丛/岩丘剪影、雾带 | 飘叶/萤火粒子（≤20 个，上浮+横飘）；雾带缓慢平移 |
| 近景 | 1.0 | 地面草地、草丛簇、花石点缀 | 草丛正弦摆动（rotate ±3°，2~3s 周期）；主角/敌人站在本层 |

全局动效：受击 screenshake（4px / 120ms）；技能释放近景轻微 zoom pulse（1.0→1.02→1.0）。

**实现约束**：三层各为一张预渲染离屏 canvas tile（程序化绘制渐变+剪影多边形，**不新增贴图依赖**），每帧各 1~2 次 `drawImage`；粒子总数 ≤40；禁用逐粒子对象绘制。视差系数仅用于层间相对运动（镜头固定时表现为层间慢速漂移循环），不实现自由镜头。

## 4. 核心循环（双循环耦合；v0.2 双链路）

```
[三消循环] 玩家果冻拖拽 → 连通块匹配消除 → 演出(吸收→合成→图标→爆发) → 下落补位 → 连锁判定
                │
                ▼ 唯一入口（见第 6 节）
        消除事件 {元素X, 数量N, 连锁c}
                │
                ▼
        X 行档位充能 +tier(N,c)（封顶5；锚点 3/6/9/12+）
                │
                ▼
[战斗循环·双链路]
  主角链：装配槽技能 CD 就绪 → 按技能等级强度自动释放（无档位）
  消除触发链：档位≥1 → 已拥有且CD就绪的同属性技能随机一个 → 选技建预约(占用池全部值) → 按时序执行(03文档4.0)
                │                          │
                ▼                          ▼
        波次推进 → Boss 波            货币/材料 → 局外养成（升级/抽卡）
```

- 三消消除是**档位与消除触发链技能的唯一来源**；战斗区不产生任何回推棋盘的效果（原型期，避免双向耦合）。主角链装配技能由 CD 驱动、不依赖三消（v0.2 双链路，见 03 文档 4.0）。
- 主角普攻不存在（D5/D11）：主角链输出=装配技能 CD 自动释放；消除触发链输出=消除驱动的额外独立释放（v0.2，见 03 文档第 4 节）。

## 6. 关键数据流：三消 → 技能（唯一入口；v0.2）

```js
// board/match.js 产出（唯一入口事件；charge.js 是充能唯一消费者，随机触发在 cast.js）
{ type: 'match_cleared', element: 'fire', count: 4, chain: 2 }
```

- `skills/charge.js` 将其转为该行档位增量：`tier_of = min(1 + ⌊(count−3)/3⌋, 5)`、`tier_gain = min(tier_of + min(chain−1, 2), 5)`（锚点区间 3~5/6~8/9~11/12~14/15+，公式与数字例见 02 文档第 5 节、03 文档第 4 节）。
- 消除触发链消费档位：每帧判定，从**已拥有且 CD 就绪且未预约**的同属性技能中均匀随机一个，选技建预约（占用池全部值为 tier，池清零），执行按 03 文档 4.0 时序（不要求装配；候选池空则档位保留）。
- 击杀/通关产出事件 `{type:'kill_reward'|'victory_reward', coins, mats}`（v0.2 新增，economy.js 唯一消费者）。
- 战斗区任何系统**不得**调用 board 模块；board 模块**不得**直接调用 executor——只发事件，单向解耦。

## 7. 持久化（D13，localStorage 键位草案；v0.2）

| 键 | 内容 |
|---|---|
| `ssww.profile` | `{ schemaVer: 2, level, coins, materials, ownedSkills[], skillLevels{id:lv}, unlockedLevel, loadout[4], settings }`（v0.2：coins/materials/ownedSkills/skillLevels 取代 exp；ownedSkills 初始=5 初始弹） |
| `ssww.progress` | `{ lastLevelCleared, bestChains }`（预留） |

- **旧档切换规则（裁决 F6）**：读取时校验 `schemaVer`——缺失或 ≠2 的存档（含 v0.1 的 exp 体系档）视为**不兼容**：删除 `ssww.profile` 与 `ssww.progress` 两键并回落新档默认（level=1、coins=0、materials=0、ownedSkills=初始 5 弹、unlockedLevel=1、默认装配）。旧档的等级/装配/关卡进度**不迁移**（产品取舍：原型期玩家档作废，已记录于 changelog；上线后如需迁移另立方案）。
- 写入时机：升级、抽卡、技能升级、**胜负结算（含失败——局内获得的货币/材料在失败时同样入账写档，05 文档第 2 节「失败收益不清退」）**、装配变更、设置变更（事件驱动，非每帧）。
