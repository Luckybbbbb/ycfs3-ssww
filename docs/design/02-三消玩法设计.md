# 02 - 三消玩法设计

> 版本 v0.1（草案）。上游：[00-宏观框架.md](00-宏观框架.md) 第 4/6 节。本文档只管棋盘；技能侧消费规则见 [03-主角技能设计.md](03-主角技能设计.md)。

## 1. 棋盘规格

| 项 | 值 |
|---|---|
| 尺寸 | 8×8 = 64 格 |
| 单格 | 90×90 逻辑像素，棋盘 720×720，位于 y=504~1224 |
| 元素 | 金木水火土 5 种，生成权重各 20% |
| 配色 | 沿用 extraction-shooters 五行色（`prototype/js/const.js:6-8`）：金 `#ccccff`、木 `#44ff44`、水 `#4488ff`、火 `#ff4444`、土 `#cc8844` |
| 棋子表现 | 原型期用五行色圆形+汉字（金木水火土），后续可换贴图 |

## 2. 交换规则（D4）

- 输入：拖动（按下→滑过相邻格）或点选（点 A 再点相邻 B）。
- 仅相邻（上下左右）可交换；交换后无匹配 → 0.15s 内回弹，棋盘状态不变、不惩罚。
- 道具格可被交换（换位），但不参与颜色匹配。

## 3. 匹配与消除

- 判定：横或竖连续 ≥3 同元素。
- 交叉形（L/T/十字）合并为**一次**消除事件，`count` = 参与格数（例：L 形 5 子 → count=5）。
- 每个匹配连通块产出一个事件（交叉 L/T 形属同一块、合并为一次，见上条）；同一轮内多块 → 多个事件，逐轮落定后立即发出（聚合细则见 5.1）。

## 4. 下落、补位与连锁

1. 消除格清空 → 该列上方棋子逐格下落（补间 ~80ms/格）。
2. 顶部空位补新随机棋子（避免与左二/上二成三连，同 FR-2.1 生成规则）。
3. 落定后重新全盘匹配；有新匹配 → 连锁级 `chain +1`，回到步骤 1；无 → 稳定，结算。

- `chain` 从 1 起：首轮消除 chain=1，第一轮连锁 chain=2，依此类推。

## 5. 消除事件与档位充能（联动核心，D8/D9）

### 5.1 事件格式与聚合范围（唯一出口）

```js
{ type: 'match_cleared', element: 'fire', count: 4, chain: 2 }
```

**聚合规则**：
- 事件**按轮聚合**：每一轮消除（含交叉 L/T 形合并，见第 3 节）在落定后立即发出该轮全部事件，**不跨轮合并、不延迟**。chain 取当轮值。
- 同一轮内多组同元素独立匹配：**各发各的事件，不合并 count**（例：同轮两组火三连 → 两个 `{count:3}` 事件）。
- 消耗品生成按**单事件 count** 判定（count=4 → 普通；count≥5 → 高级），不按轮累计——同轮两组三连不生成道具。

**跨连锁档位例**（前提：该行技能 CD 未就绪或未装配——档位才得以保留累加；若 CD 就绪则首轮充能即释放清零，不存在跨轮累加）：chain1 火三连（+1）→ chain2 火三连（1+min(1,2)=+2）→ 行档位共 3。两轮独立结算，不合并为 count=6。

### 5.2 档位增量公式

```
base_tier(count) = 1 (count=3) | 2 (count=4) | 3 (count≥5)
tier_gain = min( base_tier(count) + min(chain − 1, 2), 5 )
```

- 档位按元素行**累加**，封顶 5；累到 5 后继续消除该行不再增加（溢出浪费，无补偿提示）。
- 充能消费与释放门控见 03 文档第 4 节。

### 5.3 数字例（TDD 第 14 条覆盖 3/4/5/6 连）

| 场景 | count | chain | 计算 | tier_gain |
|---|---|---|---|---|
| 普通三连 | 3 | 1 | 1 + 0 | **1** |
| 四连 | 4 | 1 | 2 + 0 | **2**（另掉普通消耗品，见第 6 节） |
| 五连 | 5 | 1 | 3 + 0 | **3**（另掉高级消耗品） |
| 六连 | 6 | 1 | 3 + 0 | **3**（≥5 封顶于 base，不再升） |
| 三连 + 一轮连锁 | 3 | 2 | 1 + 1 | **2** |
| 三连 + 三轮连锁 | 3 | 4 | 1 + 2（min(3,2) 封顶） | **3** |
| 累加示例：先 4 连再 5 连（同元素；前提同上，档位未被释放） | — | — | 2 + 3 = 5 | 行档位到 **5** 封顶 |

## 6. 消耗品道具格（D10）

| 项 | 普通（四连掉落） | 高级（≥5 连掉落） |
|---|---|---|
| 回血 | 恢复 30% maxHP | 恢复 45% maxHP |
| 无敌 | 3.0s | 4.5s |
| CD 加速 | 5s 内技能 CD 流速 ×2 | 7.5s 内 ×2 |

- 生成：占用消除后任一空格（优先消除区域中心格），随机一种（三类等概率 1/3）。
- 表现：格内图标 + 10s 倒计时圈；可交换、不参与匹配、不阻挡下落（下落时随棋子同行）。
- 点击：立即生效并移除；超时：淡出移除，不补偿。
- **移除后的格子处理**：走标准「下落补位」——该列上方棋子下落、顶部补新棋子（沿用第 4 节流程），落定后照常匹配判定（可引发连锁并正常发事件）。移除瞬间处于 FALLING/RESOLVING 时，待当轮结算落定后追加一次下落（不与当轮动画重叠）。
- 洗牌（第 8 节）保留道具格位置不变（仅重排棋子）。

## 7. 状态机（TDD 第 15 条对象）

```
IDLE ──交换请求──► SWAPPING ──有匹配──► RESOLVING（消除动画）
  ▲                    │无匹配               │
  │                    ▼                     ▼
  └──────回弹(0.15s)◄─┘              FALLING（下落补位）
  ▲  ▲  ▲                                     │落定重匹配
  │  │  │                        有新匹配（chain+1）│无
  │  │  └──瘫痪恢复成功(PARALYZED→IDLE)            ▼         ▼
  │└──────道具超时/定时(2s)重试成功◄──PARALYZED◄──SETTLE（终态校验失败且
  │                                    │       恢复链洗牌3次+重生成50次均失败；
  │                                    └─重试失败留在 PARALYZED，
  │                                      保留下一轮 2s 定时触发）
  └────── SETTLE（终态校验通过；事件已于每轮 RESOLVING 落定时发出，见 5.1）
```

- **状态机补充（PARALYZED 为一等状态）**：SETTLE 校验失败且恢复链（洗牌 3 次 + 重生成 50 次）穷尽 → PARALYZED；PARALYZED 内部两个自循环转移（道具超时重试、2s 定时重试）**不经过 IDLE**，重试成功才走 PARALYZED→IDLE 出口。因此「洗牌仅在 IDLE 触发」指普通死局扫描（SETTLE 失败后的第一次恢复链），不含瘫痪态内部重试。

- **输入策略（选定）**：SWAPPING/RESOLVING/FALLING 期间新交换请求**忽略**（不入队、不缓存）。
- **终局一致性比较口径**：在**相同已接受操作序列 + 相同随机种子（下落补位/洗牌用）+ 相同模拟时钟**（模拟时钟 = 游戏内统一计时，含道具倒计时与动画补间）的条件下，含中断与无中断两轮的棋盘终态逐格一致。忽略策略下被忽略的输入不改变任何状态，故该口径成立；回归用例按此口径构造（固定种子驱动）。
- 洗牌触发入口（第 7/8 节统一口径）：**普通死局洗牌**仅在 IDLE 终态校验失败时触发（见第 7 节状态机 SETTLE）；**瘫痪态恢复重试**是 PARALYZED 态内部的独立转移（见第 8 节双恢复转移），不受「IDLE 才可洗牌」限制——重试失败仍停留在 PARALYZED 并保留下一次 2s 定时触发，恢复成功经 PARALYZED→IDLE 转移出口。

## 8. 死局检测与洗牌

- 每次进入 IDLE 前扫描：存在任一交换可产生匹配 → 正常；否则提示「洗牌」并重排（道具格不动）。
- **元素配额**：重排前检查各元素棋子数（道具格不计）。某元素 <3 只时，从**当前数量最多**的元素随机抽取棋子改设为该元素，直至每种 ≥3 只。**禁止反向替换**。若棋子总数 <15（道具占格过多导致），先**移除最旧的道具格**（走第 6 节移除流程：标准下落补位补入新棋子），使棋子数 ≥15 再做配额——道具移除必然发生（点击或 10s 超时），故该前置总能达成。
- **可解性验证（机械规则，不靠概率声明）**：候选棋盘必须同时满足两个条件才算合法终态：(a) **无现成匹配**（全盘匹配判定为空）；(b) `has_valid_swap()` 为真——严格定义：存在某相邻交换，交换后**被交换的两子之一参与新匹配**（只查全盘有匹配不够，会把现成匹配误判为有效）。不通过 → 再洗。注意：仅「无初始三连 + 数量均衡」**不保证**存在合法交换（反例：元素 = (行+列) mod 5 的 8×8 棋盘，各元素 12~14 只、无初始三连、但 0 个合法交换），故验证步骤不可省略。
- **有限恢复链 + 瘫痪态双恢复转移**：洗牌+验证上限 3 次 → 失败则**重新生成**（与开局同规则：随机填充含无初始三连 + 上述 (a)(b) 双验证，道具格保留原位；因生成器本身含三连规避，合法性由验证保证）→ 重新生成上限 50 次。密集道具造成几何不可解时，重生成同样可能连续失败，这是**承认的非零概率**，不假装必然可解——最终结果为**棋盘瘫痪态**：战斗区继续、三消区停止产出，UI 提示「使用或等待道具过期」。
- **瘫痪态恢复转移（P1 修订：无道具也必有出口）**：瘫痪态下存在两条恢复转移，均不依赖任何前提棋盘状态——
  1. **道具超时转移**：瘫痪态下道具倒计时**继续**（第 6 节 10s 超时承诺在瘫痪态同样成立），任一道具超时移除（走标准下落补位）后立即重试一轮恢复链；
  2. **定时重试转移**：瘫痪态每 **2s** 自动重试一轮（洗牌 3 次 + 重生成 50 次），**无次数上限**。每轮以同一 rng 流独立抽样，单轮成功率 P>0（50 次重生成从未在 M1 全部测试中单轮失败，经验 P>0.98），连续 k 轮失败概率 (1−P)^k → 0，故恢复时间概率收敛；**可机械复算的实测数字例**（tests/board.test.mjs「无道具瘫痪盘」用例，2026-10-16）：向稳定盘注入「元素 = (行+列) mod 5」死局盘（该盘 0 个合法交换、无道具、无法靠道具转移恢复），seed=7 / 42 / 99 三例均在瘫痪后**第 1 个定时重试轮内恢复**（实测恢复耗时均 2.00s），恢复后终态满足 (a)+(b) 双验证。该用例即「无道具 + 最后一次重试失败也无出口」反例的修复证明：定时转移与道具无关，必然存在。
