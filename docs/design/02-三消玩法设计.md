## 2. 交换与拖拽手感（v0.2 重做）

### 2.1 输入模型

- **任意方块按下即可拖动**（不再要求「交换必须产生匹配才放行」）；无效操作的表现是**回弹**，不是拒绝。
- 两种输入并存：
  - **拖动**：按下 P 并移动，方块跟手（见 2.2）；拖动位移越过半格阈值（45px）且方向指向某相邻格 → 立即与该格尝试交换。交换有效 → 进入消除流程；无效 → 方块继续跟手，**松手时回弹**。
  - **点选**：点 A 再点相邻 B → 立即尝试交换；无效 → A/B 各自回弹。
- 道具格可被交换（换位），但不参与颜色匹配。

### 2.2 果冻手感（表现层，不改逻辑状态）

- **跟手位移**：方块视觉偏移 = 指针位移 × 阻力系数 **0.5**，且模长钳制在 **40px** 内（像被弹性绳拴在原格中心，拖得越远阻力感越强）。
- **挤压形变**：沿拖动方向拉伸 `1 + 0.08 × (位移/40px)`、垂直方向压缩同比例（体积感守恒）；松手回弹时反向过冲一次（弹簧感）。
- **回弹动画**：**160ms** easeOutBack（过冲 ~10% 后归位）；回弹期间该方块不接受新拖动（其余方块不受影响）。
- 拖动中的方块仍参与背景列的既有动画规则（若处于 FALLING 等忙态，输入整体忽略——沿用第 7 节输入策略）。

### 2.3 交换判定的逻辑口径

- 交换有效性判定沿用「交换后新匹配须涉及被交换两子之一」（第 8 节 (b) 的同款严格判定），但**判定的时机后移**：拖动过阈值或点选时即尝试，无效仅记录「待回弹」标记，不改动棋盘数据；松手后播放回弹。逻辑状态机（第 7 节）不变——无效交换从不进入 SWAPPING。

## 3. 匹配与消除（v0.2 重做）

- **判定（v0.2）**：对每个同元素**正交连通块**（四邻接 flood fill，道具格不参与），满足任一条件即整块消除：
  1. 块内含**横或竖 ≥3 连线**（原规则保留）；或
  2. 块大小 **≥4 格**（任意形状：L 型 4 格、2×2 方块、S/Z 异形、大连通块，数量无上限）。
- **不消除**：1~2 格连通块；**3 格 L 形**（无 3 连线的折角形）。
- 每个匹配连通块产出一个事件，`count` = 整块格数（连通块天然合并交叉形，L/T/十字不再需要并查合并步骤）；同一轮内多块 → 多个事件，逐轮落定后立即发出（聚合细则见 5.1）。
- **连通块数字例**：

| 局面 | 连通块 | 判定 | 结果 |
|---|---|---|---|
| 横向 3 连 | 3 格含横线 | 条件 1 | 消除，count=3 |
| 竖向 3 连 | 3 格含竖线 | 条件 1 | 消除，count=3 |
| L 型 4 格（2+2 折角） | 4 格无 3 连线 | 条件 2 | 消除，count=4 |
| 2×2 方块 | 4 格无 3 连线 | 条件 2 | 消除，count=4 |
| L/T/十字 5 格 | 5 格 | 条件 2 | 消除，count=5（v0.1 行为保持） |
| 3 格 L 形（2+2 共角缺一臂） | 3 格无 3 连线 | 均不满足 | **不消除** |
| 孤立/两连 | 1~2 格 | 均不满足 | 不消除 |

- **开局/洗牌/重生成的「无现成匹配」升级为 v0.2 口径**：全盘无任何满足上述条件的连通块（即无 3 连线**且**无 ≥4 连通块）。生成器按 M6 口径逐色规避 3 连**并尝试规避 ≥4 连通块**（局部 flood fill 检查，REQ-M6 批次 A 落实——新规则下仅防 3 连会引发补位无限连锁），残余由重试 + 双验证收口（第 8 节流程不变，重试上限足以覆盖）。
- **消耗品生成**按单事件 count 判定不变（count=4 → 普通；count≥5 → 高级）——v0.2 下 L 型 4 格、2×2 也掉普通道具。

### 3.1 消除演出（v0.2 新增；纯表现层，事件时序见下方冻结口径）

消除**事件确立**（消除轮落定，RESOLVING 态开始）后，每个连通块播放四段演出，总时长 **0.9s**（替代原 0.20s 淡出；状态机推进时钟同步改为 0.9s，TDD 第 15 条终态一致性口径不受影响——模拟时钟含动画补间）：

| 段 | 时长 | 表现 |
|---|---|---|
| ① 吸收聚集 | 0.35s | 连通块全部方块沿贝塞尔曲线向**块质心**汇聚（错峰启动 ≤80ms，果冻挤压形变随距离增强） |
| ② 合成闪光 | 0.15s | 聚拢体白闪 + 收缩到 0.5 倍，五行色粒子迸发 ≤8 个 |
| ③ 图标浮现 | 0.25s | 质心处浮现已触发的**强化技能图标**——M10 起为 codex 生图技能贴图(assets/icons/skills/<id>.png 56px,id 与 library 一致)+下方技能名+档位星标,上浮 20px;缺图回退纯文字(技能名+星标) |
| ④ 爆发施放 | 0.15s | 图标放大 1.3 倍后碎裂，径向光效；战斗区按 03 文档 4.0 口径施放 |

- **事件与释放的时序契约（裁决 F1 冻结；与 03 文档 4.0 一致）**：
  1. **事件确立 = 演出起点（t0）**：消除轮落定同刻产出事件、档位充能、**选技尝试**（池非空 → 建预约）；段③图标显示已预约技能（有预约时）。
  2. **t0 候选池空**：段③显示「档位 +N」蓄能图标；**选技推迟到池就绪最早帧**（届时建预约），其档位留池。
  3. **释放执行时刻 = max(t0基准+本轮段④起点, 选技时刻)**（唯一规则;M9-F2:执行下限**随档位留池保存**——事件携带 `floor`(本轮段④起点偏移=0.75s×rushScale),charge 在档位首次充入时记录所属轮 floor,选技转池时预约 `execFloor=t0+floor`(t0=最早被占用档位时刻,charge.earliestT)——延迟选技/跨轮留池仍继承最早档位所属轮的执行下限,新事件不重设旧留池档位的等待时间;历史无 floor 事件回退 0.75s 口径）:发射/生效+写共享 CD+清预约同刻完成（档位已在选技建预约时占用清零）;下落补位在演出结束（t0+本轮总时长）后照常进行,不被释放阻塞。
  4. **无存活敌人**：演出照常、选技照常（预约建立）；执行挂起，敌人出现后的下一判定帧执行。
- 多块同轮消除：各块独立演出（错峰 ≤100ms）；**串行选技**（后事件池快照排除已预约技能）、行档位单一池，细则见 03 文档 4.0「同轮多块」。
- 关闭动效开关（设置）时全部四段退化为原 0.20s 淡出，逻辑时序不变。
- **连锁 RUSH 加速（M9,2026-10-17 需求方:连锁越大合成消除与补块越快,「进入 rush」）**:总时长/四段时长/段①错峰/下落时长全部乘 `rushScale(chain) = chain≤1 ? 1.00 : max(0.45, 1 − 0.15×(chain−1))`——数字例:chain1=1.00(0.9s)/chain2=0.85(0.765s)/chain3=0.70(0.63s)/chain4=0.55(0.495s)/chain5+=0.45(0.405s 封底);下落 80ms/格×scale;关闭动效退化时长(0.20s)同乘 scale(中途关闭的 4.5× 加速衰减口径不变)。事件确立/释放执行等**时序契约的相对关系不变**(全部同时缩放)。
- **连锁播报(M9,2026-10-17 需求方:对标王者击杀播报)**:chain≥2 的消除轮,engine 在 `_beginRound` 追加 `{type:'chain_announce', chain}` 事件,main 转发 fx 层定版播报——文案=王者 2017 官方(×2 二连击破 #4aa8cc/×3 三连决胜 #b06fd8/×4 四连超凡 #f5a02c/×5 五连绝世 #ffd700/≥6 连锁狂潮 ×N #e05a5a);动效=左滑入+easeOutBack 定版(0.12s)→停留呼吸(至 0.62s)→上浮淡出(总 0.9s,不阻塞逻辑),配横向光带扫过(0~0.25s);chain≥4 附棋盘微震 ±2px(0.3s 衰减)。`fxEnabled=false` 不播报(与 6.1「同步关闭」口径一致)。纯 Canvas 矢量实现,无外部素材依赖。
- **播报唯一化(M11,2026-10-17 需求方:中间右侧旧「连锁 ×N」提示移除)**:render 常显提示(FR-7 右上常显)与 fx 消除点「连锁 ×N」飞字均移除——连锁信息唯一来源=本播报;粒子迸发等消除反馈保留。

## 4. 下落、补位与连锁

1. 消除格清空 → 该列上方棋子逐格下落（补间 ~80ms/格）。
2. 顶部空位补新随机棋子（避免与左二/上二成三连，同 FR-2.1 生成规则）。
3. 落定后重新全盘匹配；有新匹配 → 连锁级 `chain +1`，回到步骤 1；无 → 稳定，结算。

- `chain` 从 1 起：首轮消除 chain=1，第一轮连锁 chain=2，依此类推。

## 5. 消除事件与档位充能（联动核心，D8/D9）

### 5.1 事件格式与聚合范围（唯一出口）

```js
{ type: 'match_cleared', element: 'fire', count: 4, chain: 2 }
```

**聚合规则**：
- 事件**按轮聚合**：每一轮消除（含交叉 L/T 形合并，见第 3 节）在落定后立即发出该轮全部事件，**不跨轮合并、不延迟**。chain 取当轮值。
- 同一轮内多组同元素独立匹配：**各发各的事件，不合并 count**（例：同轮两组火三连 → 两个 `{count:3}` 事件）。
- 消耗品生成按**单事件 count** 判定（count=4 → 普通；count≥5 → 高级），不按轮累计——同轮两组三连不生成道具。

**跨连锁档位例**（前提：该属性**候选池为空**——已拥有同属性技能全 CD 中，档位才得以保留累加；池就绪后按 03 文档 4.0 每帧判定选技建预约（占用池全部值），执行按其时间线，不存在跨轮累加）：chain1 火三连（+1）→ chain2 火三连（1+min(1,2)=+2）→ 行档位共 3。两轮独立结算，不合并为 count=6。

### 5.2 档位增量公式（v0.2 修订 2：裁决 F8，公式与区间表统一）

```
tier_of(count) = min( 1 + ⌊(count − 3) ÷ 3⌋, 5 )
tier_gain = min( tier_of(count) + min(chain − 1, 2), 5 )
```

- **锚点区间表（裁决 F8：3/6/9/12 为需求方锚点=各档区间起点；公式 `min(1+⌊(count−3)/3⌋, 5)` 与此严格一致，验证见 5.3）**：

| tier | count 区间 | 锚点（区间起点） |
|---|---|---|
| 1 | 3~5 | 3 |
| 2 | 6~8 | 6 |
| 3 | 9~11 | 9 |
| 4 | 12~14 | 12 |
| 5 | 15+ | 15 |

- 档位按元素行**累加**（行单一池；选技建预约时**池全部余额转入预约并清池**，执行只消费预约、不再扣池，见 03 文档 4.0），封顶 5；累到 5 后继续消除该行不再增加（溢出浪费，无补偿提示）。
- v0.2 语义变化：档位锚点由「3/4/≥5 连」改为「消除方块数目 3/6/9/12 及以上」——**消除数量越多技能越强**的口径不变，且连通块规则（第 3 节）下大块消除更容易出现，12+ 档可经 L 型/方块/大连通块达成。
- 充能消费与释放门控见 03 文档第 4 节（v0.2：档位只驱动**消除触发链**，预约制+每帧判定）。

## 7. 状态机（TDD 第 15 条对象；v0.2 修订）

```
IDLE ──有效交换请求──► SWAPPING（交换动画 0.15s，判定时已保证有匹配）
  ▲                    │
  │                    ▼
  │                RESOLVING（消除演出 0.9s，02 文档 3.1；事件确立+充能+选技尝试在起点同刻完成）
  │                    ▼
  │                FALLING（下落补位）
  │                    │落定重匹配
  │               有新匹配（chain+1）│无
  │                    ▼         ▼
  │                （回到 RESOLVING）SETTLE（终态校验）
  ▲  ▲  ▲                              │失败→恢复链（洗牌3+重生成50）
  │  │  └──瘫痪恢复成功(PARALYZED→IDLE) │成功        │穷尽
  │└──────道具超时/定时(2s)重试成功◄──IDLE◄──┘   PARALYZED（自循环重试）
  └────── SETTLE 通过
```

- **无效交换不进状态机（裁决 F8，与 2.3 节一致）**：拖拽/点选判定为无效时，**逻辑状态不变**（不产生 SWAPPING/REBOUND 转移），回弹是**输入/表现层**行为（果冻跟手 + 松手 160ms 回弹，见 2.2）；v0.1 图中「SWAPPING→无匹配→回弹」路径废弃——SWAPPING 仅在交换判定通过（必产生匹配）时进入。REBOUND 状态保留为内部防御态（理论不可达：判定前置保证进入 SWAPPING 必有匹配）。

- **状态机补充（PARALYZED 为一等状态）**：SETTLE 校验失败且恢复链（洗牌 3 次 + 重生成 50 次）穷尽 → PARALYZED；PARALYZED 内部两个自循环转移（道具超时重试、2s 定时重试）**不经过 IDLE**，重试成功才走 PARALYZED→IDLE 出口。因此「洗牌仅在 IDLE 触发」指普通死局扫描（SETTLE 失败后的第一次恢复链），不含瘫痪态内部重试。

- **输入策略(v0.2 修订;M9 修订 2026-10-17「演出期可操作」;M11 修订 2026-10-17「任何时刻都必须可以操作」)**:
  - **IDLE**:正常交换(无效交换表现层回弹,不改变逻辑状态);
  - **RESOLVING/FALLING(消除演出/下落补位)**:**并行交换**——任意相邻非空对**立即受理并写回 grid**(M11:不再要求「立即成消」——RESOLVING 被消格已置 null 其余格逻辑静止,FALLING grid 已是落定终态,均天然支持即时换位;成消的新匹配**并入连锁下一环**由 `_beginRound` 统一重匹配发现,chain 继续递增,不成消则断连锁回 IDLE,抢位促大连锁/主动断连锁均为策略空间);交换动画槽 `parallelSwaps` **最多 3 个并发**(M11 由单槽升级;槽满转预输入缓冲);
  - **道具点击(M11)**:**任何忙态均可点**——IDLE 走标准下落补位(原有);RESOLVING 移除后与当轮消除合并、由 `_afterClear→_applyFalls` 统一补位(无永久空洞);FALLING/SWAPPING/REBOUND 移除后原地静默补新(safePick,不改动既有下落/交换动画);PARALYZED 不可点(恢复链自身管理道具超时,第 8 节);
  - **SWAPPING/REBOUND(0.15s 短动画)**:**预输入缓冲**(`swapBuffer`,只留最新意图)——回 IDLE 时自动执行缓冲请求(有效→正常交换流程;无效→表现层弹回,grid 不变);
  - **PARALYZED**:忽略(不变)。
  - v0.2 的「忙时忽略」口径由 M9/M11 修订替代;REQ-M6-06 F7 的「跨忙态手势不复活」语义保留为「跨越进**不可操作**忙态(瘫痪/暂停)仍作废」——演出期可操作忙态的手势由上述分支显式承接,既不丢失也不意外触发。
- **终局一致性比较口径**：在**相同已接受操作序列 + 相同随机种子（下落补位/洗牌用）+ 相同模拟时钟**（模拟时钟 = 游戏内统一计时，含道具倒计时与动画补间）的条件下，含中断与无中断两轮的棋盘终态逐格一致。M9 并行交换/预输入缓冲均为显式输入(在收到时即写 grid 或登记缓冲),被缓冲后未执行的无效请求仅产生表现层弹回不改 grid,故该口径成立；回归用例按此口径构造（固定种子驱动）。
- 洗牌触发入口（第 7/8 节统一口径）：**普通死局洗牌**仅在 IDLE 终态校验失败时触发（见第 7 节状态机 SETTLE）；**瘫痪态恢复重试**是 PARALYZED 态内部的独立转移（见第 8 节双恢复转移），不受「IDLE 才可洗牌」限制——重试失败仍停留在 PARALYZED 并保留下一次 2s 定时触发，恢复成功经 PARALYZED→IDLE 转移出口。

## 8. 死局检测与洗牌

- 每次进入 IDLE 前扫描：存在任一交换可产生匹配 → 正常；否则提示「洗牌」并重排（道具格不动）。
- **元素配额**：重排前检查各元素棋子数（道具格不计）。某元素 <3 只时，从**当前数量最多**的元素随机抽取棋子改设为该元素，直至每种 ≥3 只。**禁止反向替换**。若棋子总数 <15（道具占格过多导致），先**移除最旧的道具格**（走第 6 节移除流程：标准下落补位补入新棋子），使棋子数 ≥15 再做配额——道具移除必然发生（点击或 10s 超时），故该前置总能达成。
- **可解性验证（机械规则，不靠概率声明）**：候选棋盘必须同时满足两个条件才算合法终态：(a) **无现成匹配**（v0.2 口径：全盘无满足第 3 节条件的连通块——无 3 连线且无 ≥4 连通块）；(b) `has_valid_swap()` 为真——严格定义：存在某相邻交换，交换后**被交换的两子之一参与新匹配**（v0.2 下交换形成 2×2/L 型 4 连通块同样算有效匹配）。不通过 → 再洗。注意：仅「无初始三连 + 数量均衡」**不保证**存在合法交换（反例：元素 = (行+列) mod 5 的 8×8 棋盘，各元素 12~14 只、无初始三连、但 0 个合法交换），故验证步骤不可省略。
- **有限恢复链 + 瘫痪态双恢复转移**：洗牌+验证上限 3 次 → 失败则**重新生成**（与开局同规则：随机填充含无初始三连 + 上述 (a)(b) 双验证，道具格保留原位；因生成器本身含三连规避，合法性由验证保证）→ 重新生成上限 50 次。密集道具造成几何不可解时，重生成同样可能连续失败，这是**承认的非零概率**，不假装必然可解——最终结果为**棋盘瘫痪态**：战斗区继续、三消区停止产出，UI 提示「使用或等待道具过期」。
- **瘫痪态恢复转移（P1 修订：无道具也必有出口）**：瘫痪态下存在两条恢复转移，均不依赖任何前提棋盘状态——
  1. **道具超时转移**：瘫痪态下道具倒计时**继续**（第 6 节 10s 超时承诺在瘫痪态同样成立），任一道具超时移除（走标准下落补位）后立即重试一轮恢复链；
  2. **定时重试转移**：瘫痪态每 **2s** 自动重试一轮（洗牌 3 次 + 重生成 50 次），**无次数上限**。每轮以同一 rng 流独立抽样，单轮成功率 P>0（50 次重生成从未在 M1 全部测试中单轮失败，经验 P>0.98），连续 k 轮失败概率 (1−P)^k → 0，故恢复时间概率收敛；**可机械复算的实测数字例**（tests/board.test.mjs「无道具瘫痪盘」用例，2026-10-16）：向稳定盘注入「元素 = (行+列) mod 5」死局盘（该盘 0 个合法交换、无道具、无法靠道具转移恢复），seed=7 / 42 / 99 三例均在瘫痪后**第 1 个定时重试轮内恢复**（实测恢复耗时均 2.00s），恢复后终态满足 (a)+(b) 双验证。该用例即「无道具 + 最后一次重试失败也无出口」反例的修复证明：定时转移与道具无关，必然存在。
