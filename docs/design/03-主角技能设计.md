## 1. 设计原则（D5/D6/D7）

- **包装层**：全套金木水火土五行语义（棋子元素 = 技能元素）。
- **内核层**：技能行为类型全部复用 godot-roguelike 已验证的实现模式（投射物、光环、锁链、脉冲、召唤、持续伤害区域、束缚——其行为参数见 `godot-roguelike data/skill_sources/*.json` 的 8 类行为参数）。
- **双链路（v0.2）**：主角**无普攻**，常规输出全部来自装配槽技能的 CD 自动释放（D11，强度随技能养成成长）；三消消除触发的是**额外独立的技能释放**，从已解锁的同属性技能中随机、不占装配槽、不受装配影响（D8 修订）。
- 消除是档位充能与**消除触发链**的唯一驱动（消除即资源），无独立技能次数限制（D8）；主角链装配技能由 CD 驱动、不依赖三消（v0.2 双链路，见 4.0）。

## 2. 主角属性与养成（v0.2 重做：货币/材料/抽卡）

### 2.1 属性公式（不变）

```
HP(Lv)  = 100 + 15 × (Lv − 1)
ATK(Lv) = 10 + (Lv − 1)
```

### 2.2 养成资源（v0.2：局内不再产出经验）

| 资源 | 获取 | 消耗 |
|---|---|---|
| 货币 coins | 击杀 `2 + w_global`（Boss ×20）；通关 `50 × L` | 抽卡 `100`/次 |
| 材料 mats | 击杀普通怪 **1**、Boss **20**；通关 `10 × L` | 角色升级 / 技能升级 |

- 局内战斗**不产生经验**；击杀与通关的产出实时入账并在结算时写档（v0.2 取代 v0.1 的 exp 体系）。

### 2.3 角色升级（消耗材料）

```
level_up_cost(L) = round(10 × L^1.3)      # 从 Lv 升到 Lv+1 所需材料
升级即时回满 HP（战斗内升级入口取消——升级只在局外进行，见 2.6）
```

数字例（TDD 第 14 条）：

| 等级 | level_up_cost | 计算 |
|---|---|---|
| Lv1→2 | **10** | round(10×1^1.3)=10 |
| Lv2→3 | **25** | round(10×2^1.3)=round(24.63)=25 |
| Lv3→4 | **42** | round(10×3^1.3)=round(41.71)=42 |
| Lv10→11 | **200** | round(10×10^1.3)=round(199.53)=200 |

### 2.4 技能等级（消耗材料；每技能独立）

```
skill_up_cost(s, lv) = 5 × lv              # 该技能从 lv 升 lv+1 所需材料
skill_mult(lv) = 1 + 0.08 × (lv − 1)       # 技能伤害/效果强度乘数
上限 skillLv = 10（skill_mult 最大 1.72）
```

- 作用点：主角链与消除触发链共用——技能主数值（伤害/DPS/治疗/护盾量）一律乘 `skill_mult(skillLv)` 后再走档位倍率与取整口径（4.4）。
- 数字例：Lv1 技能 ×1.0；Lv3 ×1.16；Lv10 ×1.72。火弹 ATK 10 档 1：Lv1=round(10×1.0×1.0)=**10**/发；Lv3=round(10×1.16×1.0)=round(11.6)=**12**/发（一式算完，无中间取整）。

### 2.5 抽卡（消耗货币）

- **100 货币/次**，从**未拥有**的技能中均匀随机（10 个可抽技能：5 行 × Lv3/Lv6 各 1，见 5.2）；全部拥有后抽卡入口置灰。
- **重复不存在**（只从未拥有中抽，每抽必得新技能）：集齐 10 技能**恰好 10 抽、共 1000 货币**（裁决 F4：无重复模型下无期望折算，2929 的允许重复模型废弃）；全部拥有后抽卡入口置灰，多余货币留存。
- 技能解锁口径（v0.2）：**拥有即解锁**——初始拥有 5 初始弹，其余 10 技能只能经抽卡获得；消除触发链与装配槽都只使用已拥有技能（5.1/5.2）。

### 2.6 局外养成界面（FR-7 v0.2 扩展）

- 选关界面新增入口：**角色升级**（材料→等级）、**技能升级**（材料→技能等级）、**抽卡**（货币→新技能）。
- 升级即时生效并写档；战斗内不提供升级入口（升级回满 HP 语义保留在「进关时以最新等级初始化」）。

## 3. 元素自带能力（初始 5 技能，D7）

每行初始 = **单体子弹**（CD 2.0s，弹速 600，对标 roguelike `constants.gd:82-100`）+ 自带能力（数值受技能等级与档位强化）：

| 行 | 初始技能 | 行为内核 | 自带能力（随档位强化，见 4.3） |
|---|---|---|---|
| 火 | 火弹 | projectile | 灼烧：命中后 `ATK×0.2/秒 ×3s`（不叠加，刷新时长） |
| 水 | 水弹 | projectile | 减速：命中后移速/弹速 −30% ×2s |

## 4. 双链路释放架构（v0.2 重做）

### 4.0 链路总览与同刻仲裁（v0.2 修订 2：裁决 F1/F2 冻结）

```
[主角链·养成]   4 装配槽技能 ──各自 CD 就绪且敌人存活──► 按技能等级强度自动释放（无档位参与）
[消除触发链]   消除事件 {元素X, count, chain} ──► X 行档位 += tier_gain（02 文档 5.2，封顶 5）
              ──► 每帧判定：档位池 ≥1 且 存在已拥有且 CD 就绪且未预约的 X 属性技能
                   → 随机选一个 → 选技建预约（池全部余额转入预约并清池）→ 到期执行（只消费预约）
```

- **主角链**（养成线）：装配槽 4 个技能，按各自 CD 自动释放（目标选择见 5.3），强度 = 技能基础值 × `skill_mult`（2.4）。**不吃档位**——档位资源专属消除触发链。
- **消除触发链**（操作线）：消除→充能→触发；技能从**已拥有的该属性全部技能**中**均匀随机**（例：火属性拥有 {火弹、燎原弹} → 各 50%），**不要求装配到槽位**（v0.2 核心变化：v0.1 的「行装配技能」门控废弃）。
- **CD 归属（唯一，裁决 F2）**：**每个技能只有一份 CD，两条链共用**——任一链释放该技能即写入 CD，另一链在该 CD 内不得选中/不得重复发射。不存在「两链各自 CD」。
- **消除触发链的释放判定是每帧的**（裁决 F1）：`行档位池 ≥1 ∧ 候选池非空` 即选技建预约（占用池全部值为 tier，池清零），**不等下一次消除**——候选池空（全 CD 中/被预约占用）时档位保留累积（封顶 5），池就绪后的**最早判定帧**选技；「CD 恢复后须再消除一次才触发」的旧口径废弃。
- **完整时间线（裁决 F1/F2/F9 冻结；选技、预约、执行三时刻分离）**：
  1. **事件确立（t0）**：交换判定通过、消除轮落定 → 产出事件 + 档位充能（**行档位单一池**累加，封顶 5）。同刻**选技尝试**：候选池快照 = 已拥有 ∧ CD 就绪 ∧ **未被更早预约**（同轮更早事件的预约占用，见「预约机制」）；池非空且行档位池 ≥1 → 均匀随机选中技能 s，**s 进入「待释放预约」**：**占用行档位池的当前全部值作为该预约的 tier（选技时刻固定），池即清零**（不写 CD）；池空 → 图标显示「档位 +N」蓄能态，本事件不建预约，其档位留池。消除演出（02 文档 3.1）以 t0 为起点；段③图标显示**已预约**的技能（有预约时）或蓄能（无预约）。
  2. **执行时刻（唯一规则，裁决 F1；M9-F2 修订 2026-10-17）**：`执行 = max(execFloor, 选技时刻)`——`execFloor = t0基准 + 0.75s × rushScale(档位所属轮 chain)`(02 文档 3.1;chain1=0.75s/chain2=0.6375s/chain3=0.525s/chain4=0.4125s/chain5+=0.3375s)。**执行下限随档位留池保存**:事件携带 `floor`,charge 在档位首次充入时记录所属轮 floor(charge.earliestFloor),选技转池时预约 `execFloor=t0+floor`(t0=最早被占用档位时刻=charge.earliestT)——延迟选技/跨轮留池仍继承最早被占用档位所属轮的执行下限,**新事件不重设旧留池档位的等待时间**;历史无 floor 事件回退 0.75s 口径。三例（chain1, rush=1）：①池在 t0+0.10s 就绪 → 选技 0.10s、执行 0.75s（段④起点；段③图标改为显示该技能）；②池在 t0+0.80s 就绪 → 选技 0.80s、执行 0.80s（段④播放中即刻爆发）；③池在演出结束后（如 t0+2.0s）才就绪 → 选技 2.0s、执行 2.0s（无演出，直接爆发施放）。「池就绪最早帧立即执行」的旧口径废弃——池就绪只决定**选技**时刻，执行一律按本式。
  3. **执行动作**：发射/生效（按预约的 tier 形态）、写该技能共享 CD、清除预约——三者同刻完成（档位已在选技建预约时扣减，执行不再涉及池）。
  4. **下落补位**：RESOLVING 演出结束（t0+本轮总时长,M9 RUSH 缩放）后照常进入 FALLING；释放执行不阻塞下落（弹道飞行与下落并行）。
  5. **无存活敌人**：演出照常、选技照常（预约建立）；**执行挂起**（不发射、不写 CD、不消费预约），任一敌人出现后的下一判定帧执行。
- **预约机制（裁决 F2/F9，REQ-03 修订：占用=池全部值）**：
  - **占用与扣除（唯一口径，裁决 F9/REQ-04 修订）**：**选技时将行档位池全部余额转入预约并清池**（余额即该预约的 tier，此时固定）；到期预约在存在存活目标时执行，**执行只消费预约（写 CD、清预约），不再扣池**。本口径为全文唯一预约记账规则，v0.2 早前版本的其它表述一律以本条为准。
  - **记账恒等式（REQ-04/05 修订：周期与边界冻结）**：`行档位池余额 + Σ(未执行预约的 tier) = 本局有效入池累计 − 本局已执行预约 tier 之和`，在**局内任一时刻**成立。「本局有效入池累计」= 溢出截断后**实际入池**的档位数（池 4 再充 3 → 入池 1、溢出 2 不计入，累计=5）；两项累计（有效入池、已执行）均属**本局**核算周期，终局（VICTORY/DEFEAT/重试/换关）清空池与预约时**两项累计同步归零**（结束旧周期、建立全零新周期，取消损失不入账）。
  - **记账数字例（REQ-04）**：①池 5 转入 tier5 预约 → 池 0、未执行预约 tier=5，恒等式 0+5=5 ✓；②同轮两事件（各充 1）：事件1 预约 tier1（池 0）、事件2 充 1（池 1）→ 首预约执行（池仍 1、累计 2、已执行 1 → 1+0=2−1 ✓）——**执行不消耗后来充入的余额**；③未执行预约遇 DEFEAT：池 0+预约 1=累计 1，终局清空后池 0+预约 0=累计 0（同步重置）✓；④**已执行 1、剩余 1 后 DEFEAT**：池 1+未执行 0=入池 2−已执行 1 ✓，终局清空并**两项累计同步归零** → 0+0=0−0 ✓（若只归零入池累计则得 0=−1，故已执行累计必须同时归零）。
  - **t0 归属（REQ-03 修订）**：预约的执行下限 t0 取**被占用档位中最早可用时刻**（最早充入的档位等待最久，先到先占）。例：t0=0 消除留池 1 档、t0=2.80 消除再留 1 档，技能 t=3.0 就绪 → 每帧判定选技占用 2 档（tier=2），t0 基准=0 → 执行=max(0+0.75, 3.0)=**3.00**。
  - **排他**：预约中的技能——主角链判定跳过（不发射、不写 CD）；消除链后续事件的选技池快照排除之（同一技能同时至多一个预约）。
  - **与共享 CD 的关系**：预约占用的是**执行权**；CD 只在执行时写入。仲裁与执行两阶段分离后，不存在「仲裁前已写 CD」的矛盾。
  - **生命周期**：执行时清除；**VICTORY / DEFEAT / 重试 / 换关时全部预约与行档位清空，两项记账累计（有效入池/已执行）同步归零**（跨局不保留，与 startLevel 清 zones/aura 同批）。
- **同刻仲裁（裁决 F2 冻结；REQ-05 修订：预约原子建立，仲裁只引用）**：
  1. **判定与提交阶段**：主角链**意图收集**（CD 就绪 ∧ 存活敌，跳过已预约技能，**无副作用、不写 CD**）——「无副作用」仅限定主角链。消除链对每个档位池 ≥1 且池非空的属性**串行选技并原子建立预约，只转池一次**：选中技能 s 的同刻，池全部余额转入该预约（余额即 tier，池清零）——转池、tier 快照、建预约是**同一原子动作、唯一提交位置**。
  2. **仲裁阶段（只引用，不重新读池）**：消除链已建立的预约直接持有执行权；主角链集合中与之重复的技能移除（同技能合并）；其余主角链技能本帧直接执行（写 CD）。仲裁**不重新读取池确定 tier**（tier 已在步骤 1 快照固定）。
  3. **执行阶段**：消除链预约按时间线第 2 条执行；主角链已执行项即刻生效。
  - 同刻同技能 → 消除链优先（主角链合并）；同刻不同技能 → 并发（各写各 CD）——由三阶段自然得出。
  - **池 3 逐阶段数字例（REQ-05）**：火属性池 3、火弹就绪未预约——判定与提交阶段：选技得火弹，**原子转池一次**（预约 tier=3、池 0）；仲裁阶段：只引用该预约（tier 保持 3），主角链若同刻满足火弹条件则合并移除，**不重新读池**（池已是 0，重读只会得到 tier=0 或重复预约——此即禁止原因）；执行阶段：tier3 发射。全程恰产生一个 tier3 预约、池只清零一次。
- **同轮多个独立连通块（裁决 F9）**：各事件独立「充能 → 串行选技 → 预约」；**行档位是单一池**（事件充能累加；选技建预约即占用池全部值并清零）。例：同轮两只火三连、火属性仅拥有火弹（就绪）——事件 1 充 1 档 → 选技得火弹（预约 tier=1，池清零）；事件 2 充 1 档 → 池=1，但选技池空（火弹已被预约）→ 蓄能、1 档留池；事件 1 执行（写 CD 2s）后，行档位 1 ∧ 池就绪 → 每帧判定选技（占用池 1 档为 tier=1，池清零）→ 执行第二发。不违反共享 CD：两次释放间隔 ≥ 该技能 CD；「两次各 1 档触发」指两档分两次释放，第二次按 CD 门控自然延后。

### 4.1 充能与门控（消除触发链；细则见 4.0 时间线）

```
消除 X 行 → X 行档位 += tier_gain（行单一池累加，封顶 5，公式见 02 文档 5.2）
每帧判定：X 行档位池 ≥1 且 候选池非空（已拥有 ∧ CD 就绪 ∧ 未预约）→ 随机选技+建预约（占用池全部值为 tier，池清零）
执行 = max(execFloor, 选技时刻)（execFloor=t0基准+0.75s×rushScale,随档位留池保存,M9-F2）：发射/生效（按 tier 形态）、写共享 CD、清预约
候选池为空（全 CD 中/被预约占用）→ 档位保留，继续累积（封顶 5），池就绪后的最早判定帧选技
```

### 4.4 统一舍入与计算口径（v0.2 补技能等级乘数位置）

- **计算过程一律浮点，仅在数值最终作用到实体时四舍五入取整**（round，非截断）。作用点：伤害跳、每秒 DPS 跳、治疗/护盾入账、怪物面板。**技能等级乘数不产生中间取整**（裁决 F5 唯一口径）：`有效伤害 = round(基础 × skill_mult × 档位倍率 × 元素系数)` 一式算完、最终取整一次（例：ATK 10、技能 Lv3、tier3 火弹 = round(10×1.16×2.4) = **28**，而非 round(round(10×1.16)×2.4)=29）。
- **同刻事件顺序（固定）**：投射物命中 → 周期效果跳伤 → 主角链自动释放判定 → 消除触发链释放判定。周期跳伤时钟每整秒结算一次，**命中刷新只延长持续时间、不重置跳伤时钟**。
- 百分比换算按语义分两类：**减益类**（减速）「减 30%」= 属性 ×0.70；**增益/转化类**（吸血、回血、灼烧 DPS 系数）「20%」= 直接 ×0.20。内插结果按百分点记录、保留一位小数（如 35.5%）。
- **生机光环回速公式**：每秒回复 = maxHP × 0.01 × 档位倍率（4.2 表），每整秒跳伤结算取整。例：Lv12（HP 265）tier1 回 265×0.01=2.65 → **3**/s；tier5 回 265×0.046=12.19 → **12**/s。
- 敌人伤害链：`DMG(w)` 浮点 → 弹幕伤害 = round(DMG×0.5) → 命中主角取整值。例：fox 首波 DMG=8.8 → 弹幕 = round(4.4) = **4**，面板显示 = round(8.8) = **9**。
- 周期效果跳伤：每整秒结算一次 round 后的值。例：tier1 灼烧 DPS=2.0；ATK 14 时 tier3 灼烧 = 14×0.3=4.2 → 每秒跳 **4**。

### 6.3 方向口径(「按攻击方和被击飞的方向」)

- **弹道直击**:fromAngle = 弹丸速度方向 `atan2(vy, vx)`(advanceBolt 逐帧位移可取)±0.7rad 抖动。
