# TDD 与证据标准（ycfs3-ssww）

本标准提炼自上游工程（RPGDemo 七轮验收、poe2-logic 十四轮审核）教训，是本工程一切实施与送审的最低证据门槛。配套审核协议见 `审核裁决协议.md`。

## 1. RED/GREEN 语义

1. **RED 必须是合法输入的业务断言失败**。解析失败、路径拒绝、环境缺文件不是 RED；stub 形态的合格定义 = 该功能的最小合法输入走产品入口断言失败。
2. **验证必须走产品入口**。测试自造回执、哈希自比、绕过公开接口直接调私有函数，不构成行为验证。
3. 旧失败证据保留原样，不删改；中间轮失败如实列入轨迹。

## 2. 证据形态

4. **证据覆盖面 = 身份数**。逐条/逐字段对照，不是抽样断言；正负例都要全（允许 + 拒绝 + 准确错误码）。
5. **申报与日志一致**。"全绿" = 单轮总退出码 0；失败记录不覆盖、不删改。
6. **构建身份链完整**：构建命令 + 退出码 + 输入源码 SHA + 产物路径/SHA，日志头部可查。
7. **公式冻结前用具体数字反例自证**：底数、聚合范围、舍入方向各配一个可机械复算的数字例，冻结后才实现。

## 3. 集合账与依赖

8. 集合账先脚本验证再申报：kept/withdrawn/excluded 数字一致、互斥、与文件内容逐条对得上。
9. 关键只读依赖全部入 manifest 绑定 SHA：复算器、实现文件、来源明细、前置裁决。
10. 消费集合口径如实标注："有效核对集"与"保守排除集"分开列，不混用一个总数。

## 4. 范围与授权

11. 共享文件先核所有者再进写集；写集不含共享文件时给出替代方案并声明。
12. 申报范围不外推：验收通过只覆盖本轮范围；"通过一个 Task 不通过下一 Task"。
13. `mapped ≠ implemented`：只完成映射或字段计划的效果必须如实列为未实现；观察数量不作为资格依据。

## 5. 本工程玩法数值附加项

14. 数值公式测试必须含具体数字例：三消消除数量→技能强度映射（3/4/5/6 连各一例）、杀怪升级曲线（至少两个相邻等级）、技能伤害对敌人血量的实际击杀边界。
15. 状态机回归：三消棋盘的下落/补位/连锁消除序列，快速操作（连点/滑动中断）与正常节奏的终局状态一致。
16. 复用资源回归：自 godot-roguelike 拷贝的角色/敌人场景在裁剪 autoload 依赖后能独立实例化（负例：缺失依赖加载报错路径有明确诊断）。
17. 布局回归：竖屏目标分辨率下上半战斗区（35%）与下半三消区（65%）互不遮挡、不溢出（至少一个最小分辨率与一个最大分辨率各一例）。
